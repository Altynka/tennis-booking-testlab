# Тест-кейсы: бронирование кортов (ручная проверка в Postman)

Данные: корты создаются при старте сервера.

| id | Корт | Часы работы | Цена за час |
|---|---|---|---|
| 1 | Корт 1 — Центральный | 07:00–22:00 | 8000 |
| 2 | Корт 2 — Грунт | 08:00–21:00 | 10000 |
| 3 | Корт 3 — Трава | 09:00–20:00 | 15000 |
| 4 | Корт 4 — Хард, крытый | 06:00–23:00 | 12000 |

В примерах дата `2026-11-20`. Если она уже прошла, подставь любую будущую.
Сервер хранит данные в памяти: после перезапуска все брони исчезают.

Базовое тело запроса `POST /bookings`:

```json
{
  "courtId": 1,
  "customerName": "Altyn",
  "phone": "+77011234567",
  "startAt": "2026-11-20T10:00:00",
  "durationHours": 2
}
```

## Позитивные сценарии

| ID | Проверка | Запрос / изменение тела | Ожидаемый результат | Факт |
|---|---|---|---|---|
| BK-01 | Создание брони | базовое тело | 201, `status: ACTIVE`, `endAt: 2026-11-20T12:00:00`, `price: 16000` | |
| BK-02 | Получение брони по id | `GET /bookings/1` | 200, данные как в BK-01 | |
| BK-03 | Мои брони по телефону | `GET /bookings?phone=%2B77011234567` | 200, список с бронью из BK-01 | |
| BK-04 | Слоты показывают занятость | `GET /courts/1/slots?date=2026-11-20` | 200, 15 слотов; 10:00 и 11:00 `available: false`, остальные `true` | |
| BK-05 | Бронь вплотную после другой | `startAt: 2026-11-20T12:00:00`, `durationHours: 1` | 201 (12:00 не пересекается с 10:00–12:00) | |
| BK-06 | Граница: бронь до закрытия | `startAt: 2026-11-20T21:00:00`, `durationHours: 1` | 201 (корт 1 закрывается в 22:00) | |
| BK-07 | Граница: бронь с открытия | `startAt: 2026-11-20T07:00:00`, `durationHours: 1` | 201 | |
| BK-08 | Отмена брони | `POST /bookings/1/cancel` | 200, `status: CANCELLED` | |
| BK-09 | Слот освободился после отмены | `GET /courts/1/slots?date=2026-11-20` | 10:00 и 11:00 снова `available: true` | |

## Негативные сценарии: бизнес-правила

| ID | Проверка | Запрос / изменение тела | Ожидаемый статус | Ожидаемый `code` |
|---|---|---|---|---|
| BK-10 | Пересечение с бронью | пока бронь из BK-01 активна (до BK-08): `startAt: 2026-11-20T11:00:00`, 1 ч | 409 | `SLOT_TAKEN` |
| BK-11 | Время в прошлом | `startAt: 2025-01-01T10:00:00` | 400 | `BOOKING_IN_PAST` |
| BK-12 | Не начало часа | `startAt: 2026-11-20T10:30:00` | 400 | `INVALID_START_TIME` |
| BK-13 | Граница: заканчивается после закрытия | `startAt: 21:00`, `durationHours: 2` | 400 | `OUTSIDE_WORKING_HOURS` |
| BK-14 | Граница: начинается в момент закрытия | `startAt: 22:00`, 1 ч | 400 | `OUTSIDE_WORKING_HOURS` |
| BK-15 | До открытия | `startAt: 06:00`, 1 ч | 400 | `OUTSIDE_WORKING_HOURS` |
| BK-16 | Несуществующий корт | `courtId: 999` | 404 | `COURT_NOT_FOUND` |
| BK-17 | Повторная отмена | `POST /bookings/1/cancel` второй раз | 409 | `ALREADY_CANCELLED` |
| BK-18 | Отмена несуществующей брони | `POST /bookings/999/cancel` | 404 | `BOOKING_NOT_FOUND` |
| BK-19 | Отменённая бронь не блокирует слот | после BK-08 снова создать базовую бронь | 201 | — |

## Негативные сценарии: валидация

| ID | Проверка | Изменение тела | Ожидаемый статус | Ожидаемый `code` |
|---|---|---|---|---|
| BK-20 | Пустое имя | `customerName: ""` | 400 | `VALIDATION_ERROR` |
| BK-21 | Имя из пробелов | `customerName: "   "` | 400 | `VALIDATION_ERROR` |
| BK-22 | Имя 101 символ | `customerName` длиной 101 | 400 | `VALIDATION_ERROR` |
| BK-23 | Телефон без +7 | `phone: "87011234567"` | 400 | `VALIDATION_ERROR` |
| BK-24 | Телефон короче | `phone: "+7701123456"` | 400 | `VALIDATION_ERROR` |
| BK-25 | Длительность 0 | `durationHours: 0` | 400 | `VALIDATION_ERROR` |
| BK-26 | Длительность 4 | `durationHours: 4` | 400 | `VALIDATION_ERROR` |
| BK-27 | Граница: длительность 3 | `durationHours: 3` | 201 | — |
| BK-28 | Нет поля courtId | удалить `courtId` | 400 | `VALIDATION_ERROR` |
| BK-29 | Неверный формат даты | `startAt: "завтра"` | 400 | `MALFORMED_REQUEST` |
| BK-30 | Пустое тело | тело пустое | 400 | `MALFORMED_REQUEST` |
| BK-31 | Слоты без даты | `GET /courts/1/slots` | 400 | `MISSING_PARAMETER` |
| BK-32 | Неверный id корта | `GET /courts/abc` | 400 | `INVALID_PARAMETER` |

## Что проверять в каждом ответе с ошибкой

- статус и `code` совпадают с ожидаемыми
- `message` понятен человеку
- `path` — путь запроса
- `timestamp` с часовым поясом Алматы (`+05:00`)

## Примечание к BK-03

Знак `+` в адресе нужно кодировать как `%2B`, иначе сервер прочитает его как пробел
и вернёт пустой список. Это хороший пример бага на стороне клиента: запрос «работает»
(200), но результат неверный. Попробуй оба варианта и сравни.
